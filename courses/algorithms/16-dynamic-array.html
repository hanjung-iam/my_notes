    攤銷分析 資料結構

    重點摘要

    • Dynamic array：大小可以變動的陣列，同時保有 \(O(1)\) 的隨機存取。
    • 只有 Insert：陣列滿了就開一個兩倍大的新陣列並搬過去 → 陣列至少半滿，Insert 的攤銷成本 \(O(1)\)。
    • Accounting method：Insert 收 $3（$1 付實際成本，$2 存在剛插入的項目上），搬移時剛好付得起。
    • 加入 Delete：陣列只剩 25% 滿時，縮成一半大小 → 陣列至少 25% 滿；Insert 收 $3、Delete 收 $2 即可。
    • 這個問題用 Accounting method 分析最直觀。

    1. 為什麼需要 Dynamic Array

    • 陣列簡單又有效率，支援 \(O(1)\) 時間的隨機存取。
    • 有時希望陣列大小可以變動，讓項目隨時間插入或刪除（例：用陣列實作 binary heap）→ 稱為 dynamic array。
    • 一開始配置太多空間，項目不多時會浪費；先配置固定大小，不夠時再搬到更大的陣列 → 空間使用較好，但需要搬移項目。
    • 問題：能不能空間使用好，又不需要常常搬移項目？

    Algo-Lecture-16.pdf p.3–5

    2. 只處理 Insert

    Relocate Scheme（Insert only）1. Let k be the current array size
2. If the array becomes full after Insert, create a new array
   with size 2k, and relocate all items to new array

    空間使用

    假設一開始配置固定大小（例如 100）。除非項目數 < 100，否則陣列至少半滿 → 最多浪費常數空間或陣列一半的空間 → 空間使用良好。

    攤銷成本：Aggregate Method

    • \(n\) 次 Insert 的總成本 = \(n\) + 項目被搬移的次數
    • 第 100 次操作搬 100 個、第 200 次搬 200 個、第 400 次搬 400 個…
    • → 項目被搬移的次數 \(\le 2n\) → Insert 的攤銷成本 = \(O(1)\)

    攤銷成本：Accounting Method

    設 Insert 的攤銷成本 = $3：

    • Insert 後陣列沒滿 → 不用搬移；$1 支付實際成本，$2 存起來，綁在剛插入的項目上 → 上次搬移之後插入的每個項目都有 $2。
    • Insert 後陣列滿了（目前大小為 \(k\)）→ 上次搬移後插入了 \(k/2\) 個項目 → 存款 \(\ge 2\cdot(k/2)=k\) → 足夠支付搬移；搬移後存款全部用完。

    Algo-Lecture-16.pdf p.5–9

    3. 同時處理 Insert 與 Delete

    Relocate Scheme（Insert and Delete）1. Let k be the current array size
2. If the array becomes full after Insert, create a new array
   with size 2k, and relocate all items to new array
3. If the array becomes 25% full after Delete, create a new array
   with size k/2 and relocate all items to new array

    空間使用

    一開始配置固定大小（例如 100）。除非項目數 < 100，否則陣列至少 25% 滿 → 最多浪費常數空間或陣列 75% 的空間 → 空間使用還不錯。

    攤銷成本：Accounting Method

    操作攤銷成本不需搬移時需要搬移時（目前大小 \(k\)）
    Insert $3 $1 付實際成本，$2 存起來 上次搬移後至少插入了 \(k/2\) 個項目 → 足夠支付搬移
    Delete $2 $1 付實際成本，$1 存起來 陣列剩 25% 滿時，上次搬移後至少刪除了 \(k/4\) 個項目 → 足夠支付搬移

    Algo-Lecture-16.pdf p.10–13

    4. 其他分析方法

    • Aggregate Method 也可以用，但論證會比較亂。
    • Potential Method 也可以，令 \(k\) 為目前陣列大小： \[\Phi=\begin{cases} 2\cdot(\#\text{items}-k/2) & \text{if array is more than half full} \\ k/2-\#\text{items} & \text{if array is at most half full} \end{cases}\]
    • 在這個問題中，Accounting Method 最直觀。

    Algo-Lecture-16.pdf p.14

    自我測驗

    Q1. 只有 Insert 時，陣列滿了要怎麼處理？空間使用如何？

    開一個兩倍大的新陣列，把所有項目搬過去。除非項目數少於初始大小，否則陣列至少半滿。

    Algo-Lecture-16.pdf p.5–6

    Q2. 用 aggregate method 說明 Insert 的攤銷成本為什麼是 \(O(1)\)。

    \(n\) 次 Insert 的總成本 = \(n\) + 搬移次數；搬移發生在第 100、200、400… 次，總搬移次數 \(\le 2n\)，所以平均每次 \(O(1)\)。

    Algo-Lecture-16.pdf p.7

    Q3. Accounting method 中 Insert 收 $3，陣列滿（大小 \(k\)）時為什麼付得起搬移？

    上次搬移後插入了 \(k/2\) 個項目，每個存了 $2，共 \(\ge k\)，足夠支付搬移 \(k\) 個項目。

    Algo-Lecture-16.pdf p.9

    Q4. 加入 Delete 後，什麼時候縮小陣列？Delete 的攤銷成本設多少？

    Delete 後陣列只剩 25% 滿時，開一個大小 \(k/2\) 的新陣列並搬過去。Delete 的攤銷成本設為 $2。

    Algo-Lecture-16.pdf p.10, p.13
