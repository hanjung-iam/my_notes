    攤銷分析 複雜度分析

    重點摘要

    • Amortized analysis：分析任何操作序列中，每個操作的平均時間。
    • 三種方法：Aggregate（總成本 ÷ \(n\)）、Accounting（先定攤銷成本，多的存進銀行）、Potential（先定位能函數 \(\Phi\)，再算攤銷成本）。
    • 攤銷成本唯一的要求：對任何操作序列，攤銷成本總和 \(\ge\) 實際成本總和。
    • Super Stack（Push / Pop / SuperPop）與 Binary Counter（increment），每個操作的攤銷成本都是 \(O(1)\)。
    • Potential method 的條件：\(\alpha_i+\Phi_{i-1}-\Phi_i\ge a_i\)，且 \(\Phi_0=0\)、\(\Phi\) 永遠非負。

    1. 兩個範例問題

    Super Stack

    • 一般的 stack \(S\) 支援兩個常數時間的操作：\(\text{Push}(x)\) 把 \(x\) 放入 \(S\)；\(\text{Pop}()\) 移除最後放入的項目。
    • 多加一個操作 \(\text{SuperPop}()\)：移除 \(S\) 中所有項目，時間 = \(O(1+\#\text{removed items})\)。
    • 從空的 stack 開始，執行 \(n\) 個（未知的）操作。單一操作的 worst case 是多少？全部 \(n\) 個操作呢？

    Binary Counter

    • 一開始計數器的值為 0；每次 increment 後，內容變成新值的二進位表示。
    • 一次 increment 的成本 = 改變的 bit 數。例（講義圖中最左邊是最低位 \(b_0\)）：count = 5 時為 10100，count = 6 時為 01100，cost = 2。

    Algo-Lecture-14.pdf p.2–4, p.9–10

    2. Aggregate Method

    Super Stack

    分析推理\(n\) 個操作的總時間
    Naïve Push、Pop 都是 \(O(1)\)，SuperPop 可能是 \(O(n)\)（例：\(n-1\) 次 Push 後 SuperPop） \(O(n^2)\)（正確，但不是最好的）
    Better 所有 SuperPop 移除的項目數不可能超過曾經 push 的項目數 → 總共最多移除 \(n\) 個 → SuperPop 總時間 \(O(n)\)；Push、Pop 總時間也 \(O(n)\) \(O(n)\)

    不論執行哪 \(n\) 個操作、順序如何，總時間最多 \(O(n)\) → 每個操作平均 \(O(1)\)，正式稱為 amortized time。

    💡
    Amortized cost 的意思 若 OP1、OP2、OP3 的攤銷時間分別是 \(O(t_1)\)、\(O(t_2)\)、\(O(t_3)\)，則對任何含 \(n_1\) 個 OP1、\(n_2\) 個 OP2、\(n_3\) 個 OP3 的操作序列，總時間 = \(O(n_1t_1+n_2t_2+n_3t_3)\)。

    Binary Counter

    • Naïve：單一操作最多改變 \(\log n\) 個 bits → \(n\) 個操作為 \(O(n\log n)\)（正確，但不是最好的）。
    • Better：把 bits 由右到左記為 \(b_0,b_1,b_2,\dots\)。觀察：\(b_k\) 每 \(2^k\) 次操作才翻轉一次；精確地說，\(b_k\) 在第 \(x\) 次 increment 翻轉 \(\iff\) \(x\) 可被 \(2^k\) 整除。
    \[\text{total cost}=\sum_{k=0}^{\infty}\left\lfloor \frac{n}{2^k}\right\rfloor \le \sum_{k=0}^{\infty}\frac{n}{2^k} < 2n\]

    → 每個操作的攤銷成本為 \(O(1)\)。

    💡
    Aggregate Method 的步驟
    1. 求出 \(n\) 個操作的總成本（aggregation）
    2. 把總成本除以 \(n\)

    Algo-Lecture-14.pdf p.5–14

    3. Accounting Method

    就像銀行帳戶：多的錢先存起來，需要時再拿出來用。

    • 每個操作支付一個攤銷成本。
    • 攤銷成本 \(\ge\) 實際成本 → 多出來的存進銀行。
    • 攤銷成本 < 實際成本 → 不夠的部分用銀行存款補。
    ❗
    唯一的要求 對任何操作序列，攤銷成本總和 \(\ge\) 實際成本總和。Accounting method 的目標是設計攤銷成本，讓銀行永遠有足夠的錢支付實際成本；做到這點，上述要求就滿足了。

    Super Stack

    攤銷成本：Push = $2；Pop 或 SuperPop = $1。

    • Push：$1 支付實際成本，多的 $1 存進銀行，並把這 $1 想成「綁在被 push 的那個項目上」。
    • Pop / SuperPop 移除 \(k\) 個項目：實際成本 = \(1+k\)；攤銷成本支付 1，被移除項目綁著的 $1 支付 \(k\) → 永遠付得起。

    Binary Counter

    攤銷成本：每次 increment = $2。計數器中每個 bit 1 都綁著 $1。

    • 觀察：每次 increment 最多只有一個 bit 從 0 變 1，其他翻轉的 bits 都是從 1 變 0。
    • 若一次翻轉 \(k\) 個 bits：最右邊 \(k-1\) 個 bits 由 1 變 0，第 \(k\) 個 bit 由 0 變 1。
    • 用那 \(k-1\) 個 bit 1 綁著的錢翻轉它們，用攤銷成本的 $1 翻轉第 \(k\) 個 bit，剩下的 $1 存到第 \(k\) 個 bit 上 → 永遠付得起。

    Algo-Lecture-15.pdf p.3–12

    4. Potential Method

    借用物理中「位能」的概念：物體在不同狀態有不同的位能（位置越高位能越大）。講義註：Kai 認為 potential method 可以看成 accounting method 的「互補」。

    • 先固定一個位能函數 \(\Phi\) 來衡量銀行存款；位能永遠非負 → 銀行不會破產。
    • 再依此算出攤銷成本。（相對地，accounting method 是先定攤銷成本，再證明銀行永遠付得起。）
    符號意義
    \(\Phi_i\)第 \(i\) 個操作之後的位能
    \(a_i\)第 \(i\) 個操作的實際成本
    \(\alpha_i\)第 \(i\) 個操作的攤銷成本

    設定 \(\alpha_i\) 使得：

    \[\alpha_i+\Phi_{i-1}-\Phi_i\ \ge\ a_i\]

    若 \(\Phi_0=0\)，則任意 \(n\) 個操作後：

    \[\begin{aligned} \alpha_1+\alpha_2+\cdots+\alpha_n &\ge (a_1+\Phi_1-\Phi_0)+(a_2+\Phi_2-\Phi_1)+\cdots+(a_n+\Phi_n-\Phi_{n-1}) \\ &= a_1+a_2+\cdots+a_n+\Phi_n-\Phi_0 \\ &\ge a_1+a_2+\cdots+a_n \end{aligned}\]

    Super Stack：\(\Phi\) = stack 中的項目數（\(\Phi_0=0\)）

    第 \(i\) 個操作\(\Phi_{i-1}-\Phi_i\)\(a_i\)需要設定
    Push\(-1\)1\(\alpha_i+(-1)\ge 1\)\(\alpha_i=2\)
    Pop\(1\)2\(\alpha_i+1\ge 2\)\(\alpha_i=1\)
    SuperPop（移除 \(k\) 個）\(k\)\(1+k\)\(\alpha_i+k\ge 1+k\)\(\alpha_i=1\)（與 \(k\) 無關）

    Binary Counter：\(\Phi\) = 計數器中 bit 1 的個數（\(\Phi_0=0\)）

    第 \(i\) 次 increment 翻轉 \(k\) 個 bits：\(\Phi_{i-1}-\Phi_i=k-2\)、\(a_i=k\)，需要 \(\alpha_i+(k-2)\ge k\) → 設 \(\alpha_i=2\)（與 \(k\) 無關）。

    Algo-Lecture-15.pdf p.13–22

    5. Accounting vs Potential

    方法優點缺點
    Accounting比較直觀，可以追蹤金錢流向，看出「困難時期」是怎麼撐過去的需要想出好的攤銷成本設計，讓銀行永遠有足夠的錢
    Potential比較機械化：函數一固定，就一定能算出攤銷成本不好的函數可能得到很糟的攤銷成本

    Algo-Lecture-15.pdf p.23

    6. 手寫筆記補充

    • 定義：amortized analysis 是分析演算法複雜度（執行時需要多少資源，特別是時間或記憶體）的方法：分析每個操作的執行時間，算出 worst case 所需的時間，再取平均。
    • Aggregate method：分析 \(n\) 次運行的總時間，計算 upper bound \(T(n)\) 再除以 \(n\)。
    • Potential method 的直覺：\(\Phi_i\) 像是帳戶剩下的 cost；\(\Phi_{i-1}-\Phi_i\) 就是可以把帳戶中多的 potential 拿來用。

    Push12用 1 支付實際成本，1 存起來
    Pop11—
    SuperPop1 + #removed items1用這個 1 支付實際成本中的 1；移除項目的部分用 Push 時存下的 excess 支付

    → 攤銷成本永遠足夠支付實際成本。（Accounting method，Super Stack）

    自我測驗

    Q1. 為什麼 Super Stack 執行 \(n\) 個操作的總時間是 \(O(n)\)，而不是 \(O(n^2)\)？

    所有 SuperPop 移除的項目數不可能超過曾經 push 的項目數，所以總共最多移除 \(n\) 個，SuperPop 總時間 \(O(n)\)；加上 Push、Pop 的 \(O(n)\)，總共 \(O(n)\)。

    Algo-Lecture-14.pdf p.6

    Q2. Binary counter 中，bit \(b_k\) 多久翻轉一次？\(n\) 次 increment 的總成本上界？

    每 \(2^k\) 次操作翻轉一次。總成本 \(\sum\lfloor n/2^k\rfloor < 2n\)。

    Algo-Lecture-14.pdf p.12–13

    Q3. 攤銷成本唯一的要求是什麼？

    對任何操作序列，攤銷成本總和 \(\ge\) 實際成本總和。

    Algo-Lecture-15.pdf p.5

    Q4. 用 accounting method 分析 binary counter 時，銀行的錢綁在哪裡？

    計數器中每個 bit 1 都綁著 $1；翻轉成 0 時就用這 $1 支付。

    Algo-Lecture-15.pdf p.10–12

    Q5. Potential method 中 \(\alpha_i\) 要滿足什麼條件？為什麼這樣就保證攤銷成本總和 \(\ge\) 實際成本總和？

    \(\alpha_i+\Phi_{i-1}-\Phi_i\ge a_i\)。全部相加後 \(\Phi\) 互相抵消，得到 \(\sum\alpha_i\ge\sum a_i+\Phi_n-\Phi_0\)；而 \(\Phi_0=0\)、\(\Phi_n\ge 0\)，所以 \(\sum\alpha_i\ge\sum a_i\)。

    Algo-Lecture-15.pdf p.14–16
