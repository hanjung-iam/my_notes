    排序 下界

    重點摘要

    • 任何比較排序 (comparison sort) 在 worst case 都需要 \(\Omega(n\log n)\) 次比較（用 decision tree 證明）。
    • Counting Sort、Radix Sort、Bucket Sort 不是比較排序，對輸入有假設，因此可以達到線性時間。
    • Counting Sort：\(O(n+k)\)，是 stable 的；\(k=O(n)\) 時為線性。
    • Radix Sort：從最低位開始，每一位用 stable sort 排序；搭配 Counting Sort 為 \(O(d(n+k))\)。
    • Bucket Sort：輸入在 \([0,u)\) 均勻隨機分布時，期望時間 \(O(n)\)，worst case \(O(n^2)\)。

    1. Counting Sort

    引子：幫億萬富翁整理鈔票

    • 錢包裡有 \(n\) 張鈔票，共 9 種面額：$1, $5, $10, $20, $50, $100, $200, $500, $1000。
    • Merge Sort 需要 \(O(n\log n)\)，但可以更快：每種面額準備一個 bin，逐張放入對應的 bin，再從 $1-bin、$5-bin…依序收回 → 總時間 \(O(n)\)。
    • 鈔票之間沒有直接比較：我們看的是鈔票的值，依值分到正確的 bin；從小到大收回時，鈔票之間就做了間接比較。

    演算法

    排序存在陣列 \(A\) 中的 \(n\) 個 items，每個 item 的值屬於 \(k\) 個類別之一：

    Counting Sort1. Count # items in each class
2. Calculate positions in A for each class
3. Put items to the correct positions

    實作上使用 \(k+1\) 個計數器 \(c[0],\dots,c[k]\)，並用一個額外陣列 \(B\) 暫存結果，最後再把 \(B\) 複製回 \(A\)。

    📝
    例子：A = [2, 1, 2, 5, 3, 3, 1, 2]，k = 5
    class# items起始位置 pos
    121
    233
    326
    408
    518

    由左到右逐一把 item 放到 \(B\) 中該類別目前的 pos，放完後該類別的 pos 加 1。全部放完後 \(B\) = [1, 1, 2, 2, 2, 3, 3, 5]，再複製回 \(A\)。

    💡
    重點
    • 執行時間 \(O(n+k)\)；當 \(k=O(n)\) 時為線性時間。
    • Counting Sort 是 stable 的排序：值相同的 items 在排序前後的相對順序不變。

    Algo-Lecture-06.pdf p.3–21

    2. Radix Sort

    問題：給 \(n\) 個數，每個數有 \(d\) 位、是 radix-\(k\)（十進位 → radix-10、二進位 → radix-2），要怎麼排序？

    • 直覺做法：先依最高位 (most-significant digit) 排序，再分別排序最高位相同的數。但處理 \(r\) 位之後，可能會有 \(k^r\) 組。
    • Radix Sort 反過來做：
      • 一次處理一位，從最低位 (least-significant digit) 開始
      • 每一位都用 stable sort（例如 Counting Sort）依該位排序全部 \(n\) 個數
      • 每一位的處理都一樣 → 用同樣的時間、重複使用同樣的空間 → 很容易實作
    📝
    例子：1904, 2579, 1874, 6355, 4432, 8318, 1304
    回合依哪一位 stable sort結果
    Round 1個位4432, 1904, 1874, 1304, 6355, 8318, 2579
    Round 2十位1904, 1304, 8318, 4432, 6355, 1874, 2579
    Round 3百位1304, 8318, 6355, 4432, 2579, 1874, 1904
    Round 4千位1304, 1874, 1904, 2579, 4432, 6355, 8318
    每個 Round \(r\) 結束後，最後 \(r\) 位都已經排好。
    💡
    重點
    • 正確性：可以證明「經過 \(r\) 回合後，所有數已依最後 \(r\) 位排好」。
    • 用 Counting Sort 當內部的 stable sort 時，執行時間為 \(O(d(n+k))\)。

    講義思考題：給 \(n\) 個從 \([0,n^2]\) 中選出的整數，如何在 \(O(n)\) 時間內排序？（講義未附答案）

    3. Bucket Sort

    假設：\(n\) 個整數，每個都從 \([0,u)\) 中均勻隨機選出（\(n=o(u)\)），並假設 \(n\) 整除 \(u\)（若否，把 \(u\) 進位到 \(n\) 的最小倍數）。

    • Merge Sort：\(O(n\log n)\)
    • Counting Sort：\(O(n+u)=O(u)\)
    Bucket Sort1. Divide the range [0, u) into n equal-length parts
   (where a number z belongs to part ⌊z / (u/n)⌋)
2. Create one bucket for each part
3. Distribute input integers into corresponding buckets
4. Sort the integers in each bucket
5. Combine the sorted results
    📝
    例子：範圍 [0, 1000)，輸入 235, 127, 478, 873, 525, 170, 35, 990 建立 8 個 buckets → 把數字分到對應的 bucket → 各 bucket 內排序 → 依序合併。
    💡
    執行時間 \(n\) 個整數、\(n\) 個 buckets → 平均每個 bucket 1 個整數，每個 bucket 內的排序通常只牽涉少數幾個整數，甚至可以用 Insertion Sort。
    • Worst-case：\(O(n^2)\)
    • Expected：\(O(n)\)

    Algo-Lecture-06.pdf p.30–35

    4. 比較排序的下界 (Lower Bound of Comparison Sort)

    • Comparison sort：只用「比較」推得 items 之間的相對順序來排序；比較兩個 items 只知道誰比較大，不知道它們的值。
    • 適用：Insertion Sort、Selection Sort、Bubble Sort、Heapsort、Merge Sort、Quicksort
    • 不適用：Counting Sort、Radix Sort、Bucket Sort
    • 目前學過最快的比較排序是 Merge Sort 和 Heapsort，worst case 為 \(O(n\log n)\)。有沒有 \(o(n\log n)\) 的比較排序？答案是沒有。
    💡
    Theorem 任何比較排序在 worst case 下，排序 \(n\) 個相異 items 都需要 \(\Omega(n\log n)\) 次比較。
    → 因此任何比較排序的執行時間都是 \(\Omega(n\log n)\)。

    Decision Tree

    因為定理只計算比較次數，可以假設其他操作（例如移動 items）都是免費的。比較排序可以看成：先做一連串比較，再用無限多次免費操作找出正確順序。不同輸入下的執行過程可以畫成一棵樹，稱為該演算法的 decision tree：

    樹的元素代表
    Internal node一次比較
    Branch比較的結果
    Leaf一種排序順序
    📝
    例子：排序 A、B、C
    • 方法 1：依序比較 A:B、A:C、B:C，再決定順序 → 永遠用 3 次比較（樹中有些 leaf 是不可能發生的情況）。
    • 方法 2：先檢查 A < B，再檢查 B < C；只有前兩次結果不同時才比較 A:C → 有時只需要 2 次比較。

    證明

    對 \(n\) 個相異 items 的任何正確比較排序：

    1. Decision tree 是二元樹 (binary)
    2. Decision tree 有 \(n!\) 個 leaves，因為要處理輸入的所有可能順序
    \[\begin{aligned} \text{node-height of decision tree} &\ge \log(n!) \\ &= \log n+\log(n-1)+\log(n-2)+\cdots \\ &\ge (n/2)\log(n/2) = \Omega(n\log n) \end{aligned}\]

    結論：任何比較排序的 worst-case 比較次數 = decision tree 的 node-height = \(\Omega(n\log n)\)。

    Algo-Lecture-07.pdf p.2–13

    5. 手寫筆記補充

    思考題：\([0,n^2]\) 中的 \(n\) 個整數如何 \(O(n)\) 排序

    手寫筆記寫下的做法（講義未附答案）：

    1. 一次排序一位，從 LSB 開始（即 Radix Sort）；
    2. 排序時對 \(n\) 取 modulo，讓每一位都只有 \(n\) 個類別。

    手寫筆記_Sorting_DP.pdf p.14

    Bucket Sort 例子的細節

    範圍 [0, 1000)，輸入 235, 127, 478, 873, 525, 170, 35, 990（8 個數）：

    1. 每個 bucket 的長度：\(1000/8=125\)。
    2. 建立 8 個 buckets：0–125、126–250、251–375、376–500、501–625、626–750、751–875、876–999。
    3. 分配：35 │ 235, 170, 127 │ — │ 478 │ 525 │ — │ 873 │ 990。
    4. 各 bucket 內排序：第 2 個 bucket 變成 127, 170, 235。
    5. 合併：35, 127, 170, 235, 478, 525, 873, 990。

    手寫筆記：\(n\) 個整數、\(n\) 個 buckets → 平均每個 bucket 1 個（很少）元素，bucket 內排序通常很快 → expected running time \(O(n)\)。

    ⚠️
    待確認 手寫筆記 p.15 第 1 步寫成「\(100/8\to 125\)」，範圍是 [0, 1000)，上方寫為 \(1000/8=125\)，請對照確認。

    手寫筆記_Sorting_DP.pdf p.14–15

    下界的兩種說法

    • 任何 comparison sort 都要 \(\Omega(n\lg n)\) 時間；任何 comparison sort 都要用 \(\Omega(n\lg n)\) 次比較來排序。
    • Decision tree 至少有 \(n!\) 個 leaves（\(n\) 個元素的所有排列）→ node-height \(\ge\lg(n!)\ge\frac n2\lg\frac n2=\Omega(n\lg n)\)。

    手寫筆記_Sorting_DP.pdf p.16

    自我測驗

    Q1. 什麼是 stable 的排序？Counting Sort 是 stable 的嗎？

    值相同的 items 在排序前後出現的順序相同。Counting Sort 是 stable 的。

    Algo-Lecture-06.pdf p.21

    Q2. Radix Sort 從哪一位開始處理？每一位要用什麼樣的排序？

    從最低位 (least-significant digit) 開始；每一位都用 stable sort（例如 Counting Sort）。

    Algo-Lecture-06.pdf p.24

    Q3. 以 Counting Sort 為內部排序時，Radix Sort 的執行時間？

    \(O(d(n+k))\)。

    Algo-Lecture-06.pdf p.29

    Q4. Bucket Sort 的 worst-case 與 expected 執行時間？

    用 Insertion Sort 排每個 bucket 時，worst-case \(O(n^2)\)，expected \(O(n)\)。

    Algo-Lecture-06.pdf p.35

    Q5. 為什麼 decision tree 的高度至少是 \(\log(n!)\)？

    Decision tree 是二元樹，且必須有 \(n!\) 個 leaves 來處理 \(n\) 個 items 的所有可能順序。

    Algo-Lecture-07.pdf p.12
