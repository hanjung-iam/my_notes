    重點摘要

    • MST：邊權重總和最小的 spanning tree；不一定唯一。假設邊權重都不同（相同時任意排序）。
    • Greedy Choice Lemma：每個頂點 \(v\) 最便宜的邊 \(e_v\) 一定在 MST 中。
    • Optimal Substructure：已知在 MST 中的邊 \(E^*\) 縮點後得 \(G^*\)，\(G^*\) 的 MST 加上 \(E^*\) 就是 \(G\) 的 MST。
    • Kruskal（全域最便宜的邊）\(O(E\log V)\)；Prim（source 旁最便宜的邊）binary heap \(O(E\log V)\)、Fibonacci heap \(O(E+V\log V)\)；Borůvka（每個頂點都取最便宜的邊）\(O(E\log V)\)。
    • 先跑 Borůvka \(\log\log V\) 次再換 Prim → \(O(E\log\log V)\)，\(E\) 接近 \(V\) 時比 Prim 好。

    1. Spanning Tree 與 MST

    • 設 \(G=(V,E)\) 是 connected undirected graph。\(G\) 的 spanning tree 是只用 \(G\) 的邊、連接所有頂點的一棵樹。
    • 邊有權重時（weight ⇔ 使用該邊的 cost），minimum spanning tree (MST) 是邊權重總和最小的 spanning tree。
    • MST 不一定唯一。
    年份演算法
    Borůvka [1926]第一個演算法
    Kruskal [1956]Kruskal’s Algorithm

    假設（WLOG）：邊權重都不同；若有相同，就在權重相同的邊之間給一個任意順序，讓其中一條「比較便宜」。

    Algo-Lecture-26_241214_110540.pdf p.3–7；手寫筆記_MST.pdf p.1

    2. Greedy Choice Lemma

    💡
    Theorem 令 \(e_v\) 為連接頂點 \(v\) 最便宜的邊，則 \(G\) 的 MST 對每個頂點 \(v\) 都包含 \(e_v\)。

    證明（反證法）

    1. 假設 \(G\) 的 MST \(T\) 不包含 \(e_v=(u,v)\)。
    2. 把 \(e_v\) 加進 \(T\)：\(u\)、\(v\) 原本在 \(T\) 中就連通 → 形成 cycle \((u,v,w,\dots,u)\)。
    3. 由 \(e_v\) 的定義：\(\text{weight}(e_v)<\text{weight}(v,w)\)。
    4. 刪掉 \((v,w)\)，得到一棵總權重比 \(T\) 更小的 spanning tree → 矛盾。
    ⚠️
    待確認 手寫筆記_MST.pdf p.1 的證明寫「If we delete \((v,w)\), by definition \(\text{weight}(e_v)<\text{weight}(u,w)\)」；講義 p.10 與手寫筆記_White_path_thm.pdf p.6 都寫 \(\text{weight}(e_v)<\text{weight}(v,w)\)。上方依講義整理。

    Algo-Lecture-26_241214_110540.pdf p.8–10；手寫筆記_MST.pdf p.1；手寫筆記_White_path_thm.pdf p.6

    3. Optimal Substructure

    • 令 \(E^*\) 為一組已知在 \(G\) 的 MST 中的邊。
    • 令 \(G^*\) = 把 \(E^*\) 形成的每個 connected component 縮成一個頂點後得到的圖；\(T^*\) = \(G^*\) 的 MST。
    💡
    Theorem \(T^*\cup E^*\) 是 \(G\) 的 MST。（證明：反證法，講義省略。）

    Algo-Lecture-26_241214_110540.pdf p.11–12

    4. Kruskal’s Algorithm（取全域最小）

    Kruskal-MST(G)1. Remove self-loops in G
2. Find the cheapest edge e
3. Contract e to get a graph G*
4. T* = Kruskal-MST(G*)
5. Return T* ⋃ { e }

    手寫筆記的說法：找 \(G\) 中最便宜的邊 \(e\) → 把 \(e\) 的兩個端點合成一個節點 → 遞迴地找最便宜的邊，但避免形成 cycle。

    實作與時間

    用 Disjoint Set Union-Find 實作：

    • 先依權重排序所有邊；
    • 反覆挑權重最小的邊 \(e\)：若 \(e\) 連接兩個不同的 component，就把 \(e\) 加進 MST，並做 union 連接兩個 component；否則忽略。
    \[\text{Total time}=O(\underbrace{E\log E}_{\text{sorting edges}}+\underbrace{E\,\alpha(E,V)}_{\text{union}})=O(E\log V)\]

    Algo-Lecture-26_241214_110540.pdf p.13–19；手寫筆記_MST.pdf p.1；手寫筆記_White_path_thm.pdf p.6–7

    5. Prim’s Algorithm（取局部最小）

    Prim-MST(G, u)1. Set u as the source vertex
2. Find the cheapest non-loop edge e attaching u
3. Contract e to get a graph G*
4. T* = Prim-MST(G*, u)
5. Return T* ⋃ { e }

    用 Binary Heap 實作

    • 先把所有和 \(u\) 相鄰的邊 insert 進 heap \(H\)；
    • 反覆挑權重最小的邊 \(e\)：若 \(e\) 把 \(u\) 連到一個不在 MST 中的頂點 \(v\)，就把 \(e\) 加進 MST，並把所有和 \(v\) 相鄰的邊 insert 進 \(H\)；否則忽略。
    • Total time：\(O(E\log E)=O(E\log V)\)。

    用 Fibonacci Heap 加速

    • heap 中存頂點而不是邊。
    • 一開始把所有頂點 insert 進 \(F\)，key = \(\infty\)；source \(u\) 的 key 設為 0。key = 與 \(u\) 的距離 = 把這個頂點加進 MST 的 cost。
    • 反覆挑 key 最小的頂點 \(v\)，用 \(v\) 的相鄰邊更新 \(v\) 的鄰居的 key。
    操作次數
    Insert一開始 \(O(V)\) 次
    Extract-Min總共 \(O(V)\) 次
    Decrease-Key每個頂點 \(v\) 做 \(O(\deg(v))\) 次 → 總共 \(O(E)\) 次

    → Total time \(=O(E+V\log V)\)。

    ⚠️
    待確認 手寫筆記_White_path_thm.pdf p.8 在 \(O(E+V\lg V)\) 下方的註記，把 \(E\) 標為「Decrease Min」、把 \(\lg V\) 標為「Decrease key(?)」，筆記本身也打了問號。講義 p.33 的說法是：Decrease-Key 總共 \(O(E)\) 次、Extract-Min 總共 \(O(V)\) 次。

    Algo-Lecture-26_241214_110540.pdf p.20–33；手寫筆記_MST.pdf p.1–2；手寫筆記_White_path_thm.pdf p.7–8

    6. Borůvka’s Algorithm（每個頂點都取局部最小）

    Borůvka-MST(G)1. Find the cheapest incident edge e_v for each vertex v
3. Contract all e_v to get a graph G*
4. T* = Borůvka-MST(G*)
5. Return T* ⋃ { e_v | v is a vertex of G }

    （講義原文的步驟編號為 1、3、4、5；手寫筆記把同樣的四個步驟編為 1–4。）

    時間

    • Step 1：\(O(E)\)（不需要排序邊）。
    • Step 2（縮點）：用 BFS 或 DFS，\(O(E)\)。
    • 縮點後 \(G^*\) 的每個 connected component 至少對應 \(G\) 的 2 個頂點 → \(G^*\) 的頂點數 \(\le V/2\)（手寫筆記：每次 combine 時，至少會減少一半的 vertices）。
    • Total time \(=O(E\log V)\)。

    Borůvka + Prim

    • 只跑 Borůvka \(\log\log V\) 次 → 最後的圖頂點數 \(\le V/\log V\)。
    • 此時改用 Prim： \[O(E\log\log V)+O\!\left(E+\frac{V}{\log V}\log V\right)=O(E\log\log V)\]
    • → 當 \(E\) 接近 \(V\) 時比 Prim 好（手寫筆記：在某些 condition 比兩者單獨快）。

    Algo-Lecture-26_241214_110540.pdf p.34–38；手寫筆記_MST.pdf p.2；手寫筆記_White_path_thm.pdf p.9

    7. 三種演算法比較

    演算法每一步選的邊實作時間
    Kruskal全域最便宜的邊排序 + Union-Find\(O(E\log V)\)
    Prim連接 source 最便宜的邊Binary Heap\(O(E\log V)\)
    Prim同上Fibonacci Heap\(O(E+V\log V)\)
    Borůvka每個頂點最便宜的邊BFS／DFS 縮點\(O(E\log V)\)
    Borůvka + Prim先 Borůvka \(\log\log V\) 次—\(O(E\log\log V)\)

    Algo-Lecture-26_241214_110540.pdf p.19, p.26, p.33, p.37–38

    自我測驗

    Q1. 敘述並證明 Greedy Choice Lemma。

    每個頂點 \(v\) 最便宜的邊 \(e_v\) 都在 MST 中。若 MST \(T\) 不含 \(e_v=(u,v)\)，加入 \(e_v\) 形成 cycle \((u,v,w,\dots,u)\)；因為 \(\text{weight}(e_v)<\text{weight}(v,w)\)，刪掉 \((v,w)\) 會得到更便宜的 spanning tree，矛盾。

    Algo-Lecture-26_241214_110540.pdf p.8–10

    Q2. Kruskal 用 Union-Find 實作的時間是多少？分別來自哪裡？

    \(O(E\log E+E\alpha(E,V))=O(E\log V)\)：\(E\log E\) 來自排序邊，\(E\alpha(E,V)\) 來自 union。

    Algo-Lecture-26_241214_110540.pdf p.19；手寫筆記_MST.pdf p.1

    Q3. Prim 用 Fibonacci heap 時，heap 存什麼？key 代表什麼？總時間多少？

    存頂點；key = 與 source \(u\) 的距離 = 把該頂點加進 MST 的 cost。\(O(V)\) 次 insert 與 extract-min、\(O(E)\) 次 decrease-key → \(O(E+V\log V)\)。

    Algo-Lecture-26_241214_110540.pdf p.27, p.33

    Q4. 為什麼 Borůvka 的總時間是 \(O(E\log V)\)？

    每一輪 Step 1、Step 2 都是 \(O(E)\)，而縮點後頂點數至少減半，所以最多 \(O(\log V)\) 輪。

    Algo-Lecture-26_241214_110540.pdf p.37

    Q5. 先跑 Borůvka \(\log\log V\) 次再換 Prim，總時間是多少？

    \(O(E\log\log V)+O(E+(V/\log V)\log V)=O(E\log\log V)\)，當 \(E\) 接近 \(V\) 時比 Prim 好。

    Algo-Lecture-26_241214_110540.pdf p.38
