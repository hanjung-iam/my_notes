    資料結構

    重點摘要

    • Disjoint sets 支援 Make-Set(x)、Union(x, y)、Find(x)（回傳 \(x\) 所在集合的 label）。
    • Linked list：Find \(O(1)\)、Union \(O(n)\)；加上「長的串列放前面」→ \(m\) 個操作 \(O(m+n\log n)\)，攤銷 \(O(\log n)\)。
    • Rooted tree：Find／Union 為 \(O(1+H)\)；用 Union-by-Size 或 Union-by-Rank → 樹高 \(\le\log n\)，worst-case \(O(\log n)\)。
    • 再加上 Path Compression → 攤銷 \(O(\alpha(n))\)，\(\alpha\) 是 inverse Ackermann function，實務上最多 5。

    1. 維護互斥集合

    動機（dynamic graph problem）：不時會新增頂點、在兩個頂點之間新增邊、查詢某個頂點在哪個 connected component。這對應到維護一組互斥集合，支援：

    操作作用
    Make-Set(x)建立只含 \(x\) 的集合
    Union(x, y)把含 \(x\) 的集合與含 \(y\) 的集合合併成一個
    Find(x)回傳含 \(x\) 的集合的 label
    • 通常每個集合挑一個自己的項目當 label。
    • 比較 Find(x) 與 Find(y) 回傳的 label，就能判斷 \(x\)、\(y\) 是否在同一個集合。
    • 不同方法在 Find 中找 label 的方式不同，也影響 Union 時要怎麼更新。

    Algo-Lecture-20_241204_113808.pdf p.3–5

    2. 用 Linked List 實作

    • 集合 ⇔ 一條不同的 list；集合的 label ⇔ list 的 head。
    • 為了讓 Find 為 \(O(1)\)：每個項目都有一個指向 head 的 pointer，另有一個 tail pointer 指向最後一個項目。
    • 例：\(\{\{a,b,c,d\},\{e,f,g\},\{h\}\}\) 存成三條 list：a→b→c→d、e→f→g、h。
    • Union(x, y)：把兩條 list 一前一後接起來，並更新後面那條 list 每個項目指向 head 的 pointer。例：Union(g, h) → e→f→g→h。
    Make-Set／FindUnion\(m\) 個操作總成本
    基本做法\(O(1)\)\(O(n)\)\(O(m+n^2)\)
    長的 list 放前面\(O(1)\)—\(O(m+n\log n)\)；攤銷 \(O(\log n)\)（因為 \(m\ge n\)）
    💡
    Heuristic Union 時把較長的 list 放前面，只有較短 list 的項目需要更新 pointer → 總更新量最多 \(O(n\log n)\)（講義留作思考：why?）。

    等價地，也可以把每條 list 看成一棵高度最多 1 的 rooted tree，root 當 label：Find 為 \(O(1)\)，Union(x, y) 把一棵樹的所有節點接成另一棵樹 root 的 children。

    Algo-Lecture-20_241204_113808.pdf p.6–12

    3. 用 Rooted Tree 實作

    • 集合 ⇔ 一棵不同的 rooted tree；集合的 label ⇔ 樹的 root。
    • 每個項目有一個指向 parent 的 pointer。
    • Find：沿著 parent pointer 一路走到 root → \(O(\text{tree height})\)。
    • Union(x, y)：找到含 \(x\)、\(y\) 的樹，把一個 root 接成另一個 root 的 child。例：Union(f, h)。

    設 \(H\) = 所有樹的最大高度：Make-Set \(O(1)\)；Find 或 Union \(O(1+H)\)（即 \(O(n)\)）→ \(m\) 個操作 worst-case 總成本 \(O(mn)\)。

    Algo-Lecture-21_241201_124707.pdf p.3–6

    4. 降低樹高

    Union-by-Size

    連接兩棵樹的 root 時，較小的樹的 root 成為 child。

    • 要得到高度 \(h\) 的樹，樹的節點數 \(\ge 2^h\) → 最大高度 \(H\le\log n\)。
    • → Find 或 Union 的 worst-case 為 \(O(\log n)\)。

    Algo-Lecture-21_241201_124707.pdf p.7–8

    Union-by-Rank

    時間取決於樹高，所以用和高度相關的 heuristic 更直觀：

    • 每個 root 維護一個 rank，代表樹高的 upper bound；單一節點的樹 rank = 0。
    • 連接兩個 root 時，rank 較小的 root 成為 child：
      • 兩個 rank 相同 → 連接後新 root 的 rank 加 1；
      • rank 不同 → 新 root 的 rank 不變。
    • 要得到 rank \(r\) 的 root，樹的節點數 \(\ge 2^r\) → 最大 rank \(\le\log n\) → 最大高度 \(H\le\log n\) → Find 或 Union worst-case \(O(\log n)\)。
    📝
    例子：Union(c, f) 兩棵樹的 root rank 都是 1 → 連接後新 root 的 rank 變成 2。

    Algo-Lecture-21_241201_124707.pdf p.9–12

    Path Compression

    • 看起來 rank 一直等於樹高，但還有另一個用在 Find 的 heuristic：Path Compression，它可能讓樹高變小 → 之後的操作更快。
    • 但樹高會變得很難更新 → 不更新，把 rank 當作高度的 upper bound。
    • 做法：節點離 root 越近，之後的操作越快。Find(x) 時本來就會走過 \(x\) 的所有 ancestors 才找到 root → 順便把這些 ancestors 都直接接到 root（漸進時間不會增加）。

    Algo-Lecture-21_241201_124707.pdf p.13–15

    5. 結合兩種 Heuristic

    Find 用 Path Compression，同時 Union 用 Union-by-Size 或 Union-by-Rank：

    操作Worst-caseAmortized
    Make-Set\(O(1)\)—
    Find／Union\(O(\log n)\)\(O(\alpha(n))\)

    \(\alpha\) 是 Inverse Ackermann function，實務上最多是 5。

    Algo-Lecture-21_241201_124707.pdf p.16

    Inverse Ackermann 的一些事實

    • 數列 \(n\to\log n\to\log(\log n)\to\dots\) 最後會 \(\le 1\)。令 \(\log^*\) = 取 log 幾次才會 \(\le 1\)。
    • 例：\(\log^*2=1\)、\(\log^*4=2\)、\(\log^*16=3\)、\(\log^*65536=4\)、\(\log^*2^{65536}=5\)、\(\log^*2^{2^{65536}}=6\) → \(\log^*\) 成長得非常慢。
    • 同理，令 \(\log^{**}\) = 取 \(\log^*\) 幾次才會 \(\le 1\) → 成長得更慢。
    • \(\alpha(n)>4\) 需要 \(\log^*(\log^*(\log^* n))>1\)，實務上的 \(n\) 可能做到；但 \(\alpha(n)>5\) 需要 \(\log^{**}(\log^{**}(\log^{**} n))>1\)，實務上不太可能。
    • → 實務上的 \(n\)，\(\alpha(n)\) 最多是 5。

    Algo-Lecture-21_241201_124707.pdf p.17–19

    自我測驗

    Q1. 用 linked list 實作時，Find 如何做到 \(O(1)\)？Union 要更新什麼？

    每個項目都有指向 head 的 pointer，所以 Find 直接回傳 head。Union 把兩條 list 接起來，並更新後面那條 list 每個項目指向 head 的 pointer。

    Algo-Lecture-20_241204_113808.pdf p.6, p.8

    Q2. Linked list 加上「長的放前面」之後，\(m\) 個操作的時間是多少？

    \(O(m+n\log n)\)，攤銷成本 \(O(\log n)\)（因為 \(m\ge n\)）。

    Algo-Lecture-20_241204_113808.pdf p.10

    Q3. Union-by-Rank 連接兩個 rank 相同的 root 後，rank 如何變化？

    新 root 的 rank 加 1；若 rank 不同，則 rank 較小的成為 child，新 root 的 rank 不變。

    Algo-Lecture-21_241201_124707.pdf p.10

    Q4. 為什麼使用 Path Compression 後，rank 不再等於樹高？

    Path Compression 可能讓樹高變小，但樹高很難更新，所以不更新，把 rank 當作樹高的 upper bound。

    Algo-Lecture-21_241201_124707.pdf p.13

    Q5. 結合 Path Compression 與 Union-by-Rank 後，Find／Union 的攤銷時間是多少？

    \(O(\alpha(n))\)，\(\alpha\) 為 inverse Ackermann function，實務上最多 5。

    Algo-Lecture-21_241201_124707.pdf p.16, p.19
