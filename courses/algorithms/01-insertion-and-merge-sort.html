    排序 複雜度分析

    重點摘要

    • Insertion Sort：第 \(k\) 輪把第 \(k\) 個項目往左交換，直到遇到比它小的項目為止；best case 是 linear，worst case（遞減排列）是 quadratic。
    • Selection Sort：第 \(k\) 輪找出第 \(k-1\) 個位置之後的最小值，放到第 \(k\) 個位置。
    • Merge Sort（divide-and-conquer）：切成兩半、各自遞迴排序、再合併；\(T(n)=2T(n/2)+c_1n+c_2\) → \(K_1 n\log n+K_2n+K_3\)。
    • 分析執行時間時假設電腦是 RAM：每個算術、記憶體存取、控制指令都花常數時間；本課程主要看 worst-case。
    • \(n\) 很大時，Merge Sort 的 worst-case 時間一定比 Insertion Sort 小 → Merge Sort asymptotically faster。

    1. 排序問題 (The Sorting Problem)

    • Input：\(n\) 個數字的串列；Output：把數字依遞增順序排列。
    • 排序有很多應用，例如串列排序好之後，搜尋一個數字可以更快。
    • 本講介紹 Insertion Sort、Selection Sort、Merge Sort，說明它們為什麼正確，並分析效率。

    lecture1 _240905_201432.pdf p.2–3

    2. Insertion Sort

    • 共 \(n\) 輪。第 \(k\) 輪：把第 \(k\) 個項目往左交換，直到遇到值比它小的項目才停。
    • 手寫筆記的想法：前面 \(n-1\) 個已經排好（sorted），把最後一個（Last）往左插入到正確位置，整串就排好了。
    • 手寫筆記：\(O(n^2)\)，worst case 是輸入為反向排列（reverse）。

    lecture1 _240905_201432.pdf p.4；手寫筆記_Sorting_DP.pdf p.1

    3. Selection Sort

    • 共 \(n\) 輪。第 \(k\) 輪：找出第 \(k-1\) 個位置之後的最小項目，稱為 \(X\)；把 \(X\) 插到串列的第 \(k\) 個位置。

    正確性證明（手寫筆記，數學歸納法）

    Claim：Selection Sort 能正確排序 \(n\) 個數字。

    1. \(n=1\) 時 claim 成立。
    2. 假設對所有 \(n\le k\) 成立。當 \(n=k+1\)：先選出最小的 1 個放在最前面，剩下 \(k\) 個由假設可以排好 → 整串 sorted，claim 對 \(n=k+1\) 也成立。

    手寫筆記：時間為 \(n^2\)。

    lecture1 _240905_201432.pdf p.5；手寫筆記_Sorting_DP.pdf p.1

    4. Bubble Sort（手寫筆記補充）

    • 每一輪依序比較左右 2 個數字；第 \(k\) 輪結束後，倒數 \(k\) 個數字是 sorted。
    📝
    例子 輸入 3, 5, 2, 7, 4, 6, 1 → 第 1 輪（R1）結束後：3, 2, 5, 4, 6, 1, 7（最大的 7 移到最後）。

    手寫筆記_Sorting_DP.pdf p.1

    5. Divide-and-Conquer 與 Merge Sort

    Divide-and-Conquer

    • 把大問題切成小問題 → 分別解決小問題 → 合併結果，解決原本的問題。
    • 用在排序：小問題 = 排序比較少的數字 → 把串列切成兩個較短的串列；最後把兩個排好的串列「merge」成一個。
    Merge Sort（key steps）Step 1. Divide list to two halves, A and B
Step 2. Sort A using Merge Sort
Step 3. Sort B using Merge Sort
Step 4. Merge sorted lists of A and B
    📝
    例子（手寫筆記） 5, 4, 1, 3, 6, 2 → 切成 (5, 4, 1) 與 (3, 6, 2) → 再切 → 合併出 4, 5 → 1, 4, 5；另一半 3, 6 → 2, 3, 6 → 最後合併成 1, 2, 3, 4, 5, 6。

    正確性證明（手寫筆記，數學歸納法）

    1. 假設 Merge Sort 對 \(n=1,2,\dots,k\) 都能正確排序。
    2. \(n=k+1\) 時，把串列切成兩部分，每部分有 \(\frac{k+1}{2}\) 個數字；由假設，兩個較小的串列都能被 Merge Sort 正確排序。
    3. 合併兩個排好的串列時，每次只要找出兩個串列中較小的數字 → \(n\) 個數字能正確排序。

    手寫筆記：Merge Sort 為 \(O(n\cdot\lg n)\)。

    lecture1 _240905_201432.pdf p.6–8；手寫筆記_Sorting_DP.pdf p.2

    6. 分析執行時間 (Running Time)

    RAM 模型

    • 電腦種類很多，無法直接比較實際執行時間。
    • 標準假設：電腦是 RAM (Random Access Machine)，每個算術運算、記憶體存取、控制指令（conditional jump、subroutine call、return）都花常數時間。
    • 用 RAM 操作描述演算法 → 可以數出各種操作的次數 → 量測執行時間。
    • 執行時間通常寫成輸入大小的函數（排序問題中為 \(n\)）。

    lecture1 _240905_201432.pdf p.9–10

    Insertion Sort 的執行時間

    PseudocodeINSERTION-SORT(A)                                  cost   times
1  for j ← 2 to length[A]                          c1     n
2      do key ← A[j]                               c2     n − 1
3         ▷ Insert A[j] into the sorted
             sequence A[1 .. j − 1].               0      n − 1
4         i ← j − 1                                c4     n − 1
5         while i > 0 and A[i] > key               c5     Σ_{j=2..n} t_j
6             do A[i + 1] ← A[i]                   c6     Σ_{j=2..n} (t_j − 1)
7                i ← i − 1                         c7     Σ_{j=2..n} (t_j − 1)
8         A[i + 1] ← key                           c8     n − 1

    \(t_j\) = 第 \(j\) 輪 key 被比較的次數。合併各項：

    \[T(n)=c_1n+(c_2+c_4+c_8)(n-1)+c_5\sum_{j=2}^{n}t_j+(c_6+c_7)\sum_{j=2}^{n}(t_j-1)\]

    \(t_j\) 的值取決於輸入本身（不只是輸入大小）。

    情況輸入\(t_j\)\(T(n)\)
    Best case已經排好\(t_j=1\)\(c_1n+(c_2+c_4+c_5+c_8)(n-1)=Kn+c\)，linear
    Worst case遞減排列\(t_j=j-1\)\(K_1n^2+K_2n+K_3\)，quadratic

    lecture1 _240905_201432.pdf p.11–13

    為什麼看 Worst-Case

    1. 給出執行時間的 upper bound。
    2. Worst case 相當常發生。

    備註：也有人研究 average-case（假設輸入是隨機產生的）。

    lecture1 _240905_201432.pdf p.14

    Merge Sort 的執行時間

    Pseudocode（partial）MERGE-SORT(A, p, r)
1  if p < r
2     then q ← ⌊(p + r)/2⌋
3          MERGE-SORT(A, p, q)
4          MERGE-SORT(A, q + 1, r)
5          MERGE(A, p, q, r)

    講義中 MERGE(A,p,q,r) 留作練習（提示：用一個暫存陣列來合併）。假設兩個總大小為 \(n\) 的串列 Merge 需要 \(c_1n\) 時間：

    \[T(n)=\begin{cases}2T(n/2)+c_1n+c_2 & n>1\\ c_3 & n=1\end{cases} \quad\Rightarrow\quad T(n)=K_1n\log n+K_2n+K_3\]

    lecture1 _240905_201432.pdf p.15–17

    7. 哪個演算法比較快？

    • 執行時間中的常數未知，所以還不能直接比較。
    • 但只要 \(n\) 非常大，Merge Sort 的 worst-case 時間一定比 Insertion Sort 小。
    • → Merge Sort is asymptotically faster than Insertion Sort。

    lecture1 _240905_201432.pdf p.18

    自我測驗

    Q1. Insertion Sort 的 best case 與 worst case 分別是什麼輸入？時間各是什麼函數？

    Best case：輸入已排好，所有 \(t_j=1\)，\(T(n)=Kn+c\)（linear）。Worst case：輸入遞減排列，\(t_j=j-1\)，\(T(n)=K_1n^2+K_2n+K_3\)（quadratic）。

    lecture1 _240905_201432.pdf p.13

    Q2. Selection Sort 第 \(k\) 輪做什麼？

    找出第 \(k-1\) 個位置之後的最小項目 \(X\)，把 \(X\) 插到第 \(k\) 個位置。

    lecture1 _240905_201432.pdf p.5

    Q3. 寫出 Merge Sort 的四個步驟與執行時間的遞迴式。

    切成兩半 A、B → 用 Merge Sort 排 A → 用 Merge Sort 排 B → 合併。\(T(n)=2T(n/2)+c_1n+c_2\)（\(n>1\)），\(T(1)=c_3\)，解得 \(K_1n\log n+K_2n+K_3\)。

    lecture1 _240905_201432.pdf p.8, p.17

    Q4. 為什麼本課程主要分析 worst-case running time？

    它給出執行時間的 upper bound，而且 worst case 相當常發生。

    lecture1 _240905_201432.pdf p.14

    Q5. 用數學歸納法說明 Merge Sort 為什麼正確。

    假設對 \(n\le k\) 都正確；\(n=k+1\) 時切成兩半，各自由假設可排好；合併時每次取兩串列中較小的數字，所以整串排好。

    手寫筆記_Sorting_DP.pdf p.2
