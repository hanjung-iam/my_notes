    堆積 攤銷分析

    重點摘要

    • Fibonacci Heap：Find-Min、Insert、Union、Decrease-Key 為攤銷 \(O(1)\)；Extract-Min、Delete 為攤銷 \(O(\log n)\)。
    • 樹的數量與高度都沒有限制；Union 只是把兩個 heap 放在一起，Extract-Min 時才 consolidate（把 degree 相同的 root 連起來）。
    • Decrease-Key：值比 parent 小就切下來變成新的樹；marking policy：第一次失去 child 時 mark，第二次失去 child 時自己也切下來（cascading cuts）。
    • Marking 保證 degree 為 \(k\) 的子樹至少有 \(F_{k+1}\) 個節點 → 任何節點 degree \(\le\log_\Phi n\approx 1.4405\log n\)。
    • Accounting method：每個 root 存 $1、每個 marked node 存 $2；Insert $2、Find-Min／Union $1、Decrease-Key $4。

    1. Fibonacci Heap 的結構

    • 和 Binomial Heap 一樣，由一組 component tree 組成，節點滿足 heap property。
    • 但和 Binomial Heap 不同：
      • component tree 的數量沒有限制（可能多達 \(n\)）→ Extract-Min 的 worst-case 是 \(O(n)\)；
      • component tree 的高度沒有限制（可能多達 \(n\)）→ 需要新的 Decrease-Key 做法。
    • 用特殊的 marking policy 讓節點的 degree 有上界。想法：如果一個節點的 degree 很大，它一定有很多子孫。之後會證明：任何節點的 degree \(\le 1.4405\log n\)。

    Algo-Lecture-18_241127_150056.pdf p.2–3, p.7；手寫筆記_binomial heap.pdf p.4

    2. 操作

    Find-Min、Union、Insert

    • Heap \(H\) 隨時維護一個指標 \(\min(H)\) 指向最小值的節點 → Find-Min 為 \(O(1)\)。
    • Union \(H_1\)、\(H_2\)：直接把兩個 heap 放在一起成為 \(H\)，並設 \(\min(H)=\min\{\min(H_1),\min(H_2)\}\)。
    • Insert 是 Union 的特例 → 兩者都是 \(O(1)\)。

    Algo-Lecture-18_241127_150056.pdf p.4–6；手寫筆記_binomial heap.pdf p.4

    Extract-Min

    1. Remove：移除最小值的 root → 它的 children 成為新樹的 root。
    2. Consolidate：反覆把 degree 相同的 root 連起來 → 最後所有 root 的 degree 都不同。
    3. Update：更新 \(\min(H)\)。
    • Consolidate 時以任意順序逐一檢查每棵樹；使用陣列 \(A[1..M]\)（\(M\) = 所有節點的最大 degree），\(A[k]\) 存一棵 root degree 為 \(k\) 的樹。
    • 任何時候每種 degree 最多保留一棵樹；若有兩棵，就把它們的 root 連起來。
    📝
    例子（講義與手寫筆記） 移除 \(\min(H)=8\) 後，它的 children 25、13 成為 root → 25 與 13（degree 0）連接成 13–25 → 12 與 13（degree 1）連接，12 成為 root → 最後 \(\min(H)=12\)。

    Algo-Lecture-18_241127_150056.pdf p.8–15；手寫筆記_binomial heap.pdf p.4–5

    Decrease-Key

    • Binary／Binomial Heap 的 Decrease-Key 是和 parent 反覆交換；樹高 \(O(\log n)\) 所以有效率。
    • Fibonacci Heap 的樹高沒有上界，而且希望 Decrease-Key 是攤銷 \(O(1)\) → 用完全不同的做法：
    💡
    做法 對 \(x\) 做 Decrease-Key 後，若值比 parent 小，就把 \(x\) 從 parent 切下來，讓 \(x\) 成為一棵新樹的 root。

    但為了 Extract-Min 的效率，要避免出現「degree 很大但子孫很少」的節點 → 加上 marking：

    1. 節點 \(v\) 第一次失去 child → mark \(v\)。
    2. 節點 \(v\) 第二次失去 child → 把 \(v\) 從它的 parent 切下來，並 unmark \(v\)（避免 \(v\) 的 parent 連著一棵子孫很少的子樹）。
    ❗
    注意
    • Tree root 沒有 parent 可以切 → root 可以選擇 unmark（optional）。
    • \(x\) 從 \(v\) 切下時，若 \(v\) 已被 mark，\(v\) 也要切下，接著 \(v\) 的 parent 也可能被切…稱為 cascading cuts，最多可達 \(O(n)\)（手寫筆記：detachment 可能會有連鎖反應）。
    📝
    例子
    1. 32 降為 18：18 仍不小於 parent 15 → 不用切。
    2. 21 降為 3：3 比 parent 19 小 → 切下 3，成為新 root，\(\min(H)=3\)；19 第一次失去 child → 被 mark。
    3. 35 降為 14：切下 14；parent 27 已被 mark → 27 也切下並 unmark；27 的 parent 19 已被 mark → 19 也切下（cascading cuts）。

    Algo-Lecture-18_241127_150056.pdf p.16–24；手寫筆記_binomial heap.pdf p.5–6

    3. 最大 Degree 的上界

    設節點 \(x\) 的 degree 為 \(k\)，children 依成為 \(x\) 的 child 的時間標為 \(y_1,y_2,\dots,y_k\)（\(y_1\) 最舊）。

    • \(y_1\)、\(y_2\) 的 degree 至少為 0。
    • Consolidate 時 \(y_3\) 被加為 \(x\) 的 child，那時 \(y_1\)、\(y_2\) 都已是 \(x\) 的 children → 當時 \(\deg(y_3)=\deg(x)\ge 2\)；之後 \(y_3\) 可能失去 child（最多一個，否則會被切掉）→ 現在 \(\deg(y_3)\ge 1\)。
    • 同理 \(y_4\) 加入時 \(\deg(y_4)=\deg(x)\ge 3\) → 現在 \(\deg(y_4)\ge 2\)。
    • 一般而言，現在 \(\deg(y_j)\ge j-2\)。

    令 \(N_k\) = root degree 為 \(k\) 的子樹最少的節點數：

    \[N_0=1,\ N_1=1+N_0=2,\ N_2=1+N_0+N_0=3,\ N_3=1+N_0+N_0+N_1=5,\ N_4=1+N_0+N_0+N_1+N_2=8\]
    💡
    結論 由歸納法，\(N_k\) = 第 \(k+1\) 個 Fibonacci number \(F_{k+1}\)（這就是 Fibonacci heap 名稱的由來）。 因為 \(F_{k+1}\ge\Phi^k\)，其中 \(\Phi=\frac{\sqrt5+1}{2}\) 為黃金比例 → \[\text{Degree of any node}\le\log_\Phi n\approx 1.4405\log n\]

    Algo-Lecture-19_241201_132934.pdf p.3–6；手寫筆記_binomial heap.pdf p.6–7

    4. 攤銷成本 (Accounting Method)

    Excess 存在每個 tree root（各 $1）與每個 marked node（各 $2）上。

    操作攤銷成本說明
    Insert$2$1 付實際成本、$1 存在新 root
    Find-Min／Union$1付實際成本
    Extract-Min\(O(\log n)\)見下方
    Decrease-Key$4 = \(O(1)\)見下方

    Extract-Min

    • Consolidate 時處理 root degree 為 \(k\) 的樹，用這棵樹自己的 excess 支付：放進陣列 \(A\)、被連成另一個節點的 child、把合併後的樹移到 \(A\) 的其他格子。
    • → 除了初始化陣列 \(A\) 之外，consolidate 的實際成本都已付清。攤銷成本只需處理：
      1. 移除最小值節點 → \(O(\log n)\)
      2. 初始化陣列 \(A\) → \(O(\log n)\)
      3. 替最後的 tree roots 補充 excess → \(O(\log n)\)
      合計 \(O(\log n)\)。

    Decrease-Key（攤銷成本 $4）

    1. 目前節點沒被切下：實際成本 1 → 足夠。
    2. 被切下，且 parent 未被 mark：$1 付實際成本、$1 存在目前節點（現在是 root）、$2 存在 parent（現在被 mark）。
    3. 被切下，且 parent 已被 mark：設 cascading cuts 中有 \(c\) 個 marked node，每個用自己 $2 excess 中的 $1 付相關實際成本、$1 留著（現在是 root 且 unmarked）→ cascading cuts 的成本都已付清。攤銷成本只需處理：$1 付目前節點的實際成本、$1 存在目前節點（現在是 root）、$2 存在最後一個 cascading cut 節點的 parent。

    Algo-Lecture-19_241201_132934.pdf p.7–12；手寫筆記_binomial heap.pdf p.7–8

    5. 三種 Heap 的比較

    操作BinaryBinomialFibonacci
    Make-Heap\(O(1)\)\(O(1)\)\(O(1)\)
    Find-Min\(O(1)\)\(O(1)\)\(O(1)\)
    Insert\(O(\log n)\)\(O(\log n)\)\(O(1)\)
    Extract-Min\(O(1)\)\(O(\log n)\)\(O(\log n)\)*
    Decrease-Key\(O(\log n)\)\(O(\log n)\)\(O(1)\)*
    Delete\(O(\log n)\)\(O(\log n)\)\(O(\log n)\)*
    Union\(O(n)\)\(O(\log n)\)\(O(1)\)

    * 為 amortized time。

    Algo-Lecture-19_241201_132934.pdf p.13；手寫筆記_binomial heap.pdf p.8

    自我測驗

    Q1. Fibonacci Heap 的 Union 怎麼做？為什麼是 \(O(1)\)？

    直接把兩個 heap 放在一起，並設 \(\min(H)=\min\{\min(H_1),\min(H_2)\}\)，不需要合併任何樹。

    Algo-Lecture-18_241127_150056.pdf p.4

    Q2. Extract-Min 的三個步驟是什麼？

    移除最小值的 root（children 成為新 root）→ consolidate：反覆連接 degree 相同的 root，直到所有 root 的 degree 都不同 → 更新 \(\min(H)\)。

    Algo-Lecture-18_241127_150056.pdf p.8

    Q3. 說明 marking policy。

    節點第一次失去 child 時被 mark；第二次失去 child 時，把它從 parent 切下來並 unmark。這可能引發 cascading cuts。

    Algo-Lecture-18_241127_150056.pdf p.19, p.24

    Q4. 為什麼任何節點的 degree \(\le 1.4405\log n\)？

    第 \(j\) 個 child 的 degree \(\ge j-2\)，所以 root degree 為 \(k\) 的子樹至少有 \(N_k=F_{k+1}\ge\Phi^k\) 個節點，故 degree \(\le\log_\Phi n\approx 1.4405\log n\)。

    Algo-Lecture-19_241201_132934.pdf p.4–6

    Q5. Accounting method 中 excess 存在哪裡？Insert 與 Decrease-Key 的攤銷成本各是多少？

    每個 tree root 存 $1、每個 marked node 存 $2。Insert 為 $2，Decrease-Key 為 $4。

    Algo-Lecture-19_241201_132934.pdf p.7, p.10
