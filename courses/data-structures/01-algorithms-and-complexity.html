    複雜度分析

    重點摘要

    • 演算法：一組有順序、明確、可執行，且會結束的步驟。五個條件：Input、Output、Definiteness、Finiteness、Effectiveness。
    • 效能評估看兩件事：Space Complexity \(S(P)=C+S_P(I)\) 與 Time Complexity \(T(P)=C+T_P(I)\)。
    • 比的是成長率 (growth rate)，不是步數：\(2n+3\) 和 \(2n+2\) 的時間複雜度相同。
    • \(O\)：上界；\(\Omega\)：下界；\(\Theta\)：同時是 \(O\) 和 \(\Omega\)。多項式只看最高次項。
    • Rule of Sum 取最大、Rule of Product 相乘；Binary Search 的 worst case 為 \(O(\log_2 n)\)。

    1. 演算法的概念

    • 正式定義：演算法是一組有順序 (ordered)、不含糊 (unambiguous)、可執行 (executable) 的步驟，定義了一個會結束 (terminating) 的過程。
    • Problem = 演算法的動機；Algorithm = 解決問題的程序（通常是許多可能之一）。
    • Program：演算法正式且可執行的表示；Process：執行程式的活動。
    演算法的條件說明
    Input由外部提供零個或多個量
    Output至少產生一個量
    Definiteness每個指令都清楚、不含糊
    Finiteness在有限步之後結束
    Effectiveness每個指令都必須基本、容易計算

    演算法的表示方式

    • 自然語言（英文、中文…）：句子很多
    • 圖形表示（Flowchart）：只適合小而簡單的演算法
    • 程式語言 + 少量英文（例如 C++）：簡潔有效
    • Primitives：一組定義清楚的基本元件，用來組成演算法的表示；包含 syntax（符號表示）與 semantics（代表的概念）。

    Session1-Algorithms Handout.pdf p.3–6

    2. 解題的思考過程

    • 開發程式包含兩部分：找出背後的演算法，以及把演算法表示成程式。
    • 不存在能為任何問題產生演算法的演算法；有些問題是無法解的。解題能力比較像需要培養的藝術技巧。

    解題階段（不一定依序完成）：

    1. 理解問題
    2. 想出演算法程序可能如何解決問題
    3. 寫出演算法並表示成程式
    4. 評估程式的正確性，以及用來解決其他問題的潛力
    • Incubation periods：有意識的工作與突然的靈感之間，潛意識仍在持續運作，最後把解法推到意識中。
    • 入門技巧：從問題的結果往回推；先解一個較簡單的相關問題（放寬限制）；先解問題的一部分 = bottom-up；Stepwise refinement = top-down（常用，因為能產生模組化的程式）。
    • 邏輯思考：把大問題拆小 (Divide)，再把小問題的結果組合起來 (Conquer)。

    講義課後練習：找出日常生活中 divide and conquer 的例子。

    3. Pseudocode

    比正式程式語言更不正式、更直觀的表示系統，能在開發演算法的過程中非正式地表達想法，讓人專注在概念上（研究顯示人腦一次只能處理約 7 個細節）。Flowchart 和圖形表示也是有用的工具。

    Primitive形式

    Conditional selectionif condition then action
    Repeated executionwhile condition do activity
    Procedureprocedure name (generic names)

    Iterative Structures

    以迴圈方式重複一組指令，有四種程式區塊：

    • Initialize：建立要被修改的初始狀態
    • Test：比較目前狀態與結束條件
    • Statement：每次迭代重複執行的區塊
    • Modify：把狀態往結束條件推進
    三種迴圈While-loop:  initialize; while( test ) { activity; modify; }
Repeat-loop: initialize; repeat ( activity; modify; ) until ( test )
For-loop:    for( initialize; test; modify ) { statement; }

    Recursive Structures

    • 另一種重複結構：呼叫自己（Divide-and-Conquer）。
    • 執行時會產生多個 instance（children），每個 child 負責解決較小的問題，並把結果回傳給 parent；同一時間只有一個 instance 在推進。

    範例：Sequential Search 與 Binary Search

    Sequential Searchprocedure Search (List, TargetValue)
if (List empty)
    then
        (Declare search a failure)
    else
        (Select the first entry in List to be TestEntry;
         while (TargetValue > TestEntry and
                there remain entries to be considered)
             do (Select the next entry in List as TestEntry.);
         if (TargetValue = TestEntry)
             then (Declare search a success.)
             else (Declare search a failure.)
        ) end if
    Binary Searchprocedure Search (List, TargetValue)
if (List empty)
  then
    (Report that the search failed.)
  else
    [Select the "middle" entry in List to be the TestEntry;
     Execute the block of instructions below that is
       associated with the appropriate case.
         case 1: TargetValue = TestEntry
                   (Report that the search succeeded.)
         case 2: TargetValue < TestEntry
                   (Apply the procedure Search to see if TargetValue
                    is in the portion of the List preceding TestEntry,
                    and report the result of that search.)
         case 3: TargetValue > TestEntry
                   (Apply the procedure Search to see if TargetValue
                    is in the portion of List following TestEntry,
                    and report the result of that search.)
    ] end if

    4. 效能評估

    • 同一個問題可以有很多演算法，選擇有效率或沒效率的演算法差別很大。
    • 兩個準則：Space Complexity（用了多少記憶體）、Time Complexity（需要多少執行時間）。
    • 兩種評估方式：
      • Performance Analysis：與機器無關，事前估計 (a priori)
      • Performance Measurement：與機器有關，事後測試 (a posteriori)
    • 背景：Von Neumann 架構包含 CPU（ALU、Control Unit、Registers）、Memory Unit、Buses。

    Space Complexity

    \[S(P)=C+S_P(I)\]
    部分說明
    \(C\)：固定部分與輸入輸出無關；包含指令空間、簡單變數、固定大小的結構變數、常數
    \(S_P(I)\)：變動部分取決於問題實例；包含被參照的變數與遞迴堆疊空間 (instance characteristics)，以及輸入輸出的數量與大小
     
    例子（C++）float Abc(float a, b, c)
{
    return a+b+b*c+(a+b-c)/(a+b)+4.00;
}
// S_Abc(I) = 0, S(Abc) = C = constant

float Sum(float *A, const int n)
{   float s = 0;
    for(int i=0; i<n; i++)
        s += A[i];
    return s;
}
// S_Sum(I) = 0 (A stores only the address of array), S(Sum) = constant

float Rsum(float *A, const int n)
{
    if (n<=0) return 0;
    else return (Rsum(A, n-1) + A[n-1]);
}
// Rsum(A, n) → Rsum(A, n-1) → … → Rsum(A, 0)：共 n+1 次呼叫
    ⚠️
    待確認 p.37 中「每次 Rsum 呼叫需要的空間」與 \(S(\text{Rsum})\) 的結果，在 PDF 中沒有可讀取的文字（可能是課堂上補寫或動畫內容），請對照講義或上課筆記補上。

    Time Complexity

    \[T(P)=C+T_P(I)\]
    • \(C\)：常數部分（compile time）；\(T_P(I)\)：變動部分（running time）。
    • 用 program step 估計 \(T_P(I)\)：一個 program step = 執行時間與 instance characteristics 無關的敘述。
    Iterative Summing 的步數float Sum(float *A, const int n)
{   float s = 0;               // 1 step
    for(int i=0; i<n; i++)     // n+1 steps
        s += A[i];             // n steps
    return s;                  // 1 step
}
    Recursive Summing 的步數float Rsum(float *A, const int n)
{
    if (n<=0)                               // 1 step
        return 0;                           // 1 step
    else return (Rsum(A, n-1) + A[n-1]);    // 1 step
}

    結果：\(T_{\text{Sum}}(n)=2n+3\) steps，\(T_{\text{Rsum}}(n)=2n+2\) steps。（\(T_{\text{Rsum}}\) 的遞迴推導過程在 p.40 沒有可讀取的文字。）

    ❗
    易錯：步數少 ≠ 比較快 不能說 Rsum 比 Sum 快，因為每個 step 的執行時間不同。我們在意的是成長率：輸入變 10 倍時，兩者的執行時間都變 10 倍（linear time），所以兩者的時間複雜度相同。

    Session1-Algorithms Handout.pdf p.27–42

    5. 漸進符號 (Asymptotic Notation)

    比較複雜度時要看 \(n\) 夠大的情況。例：\(P_1=n^2+2n\)、\(P_2=100n\) 或 \(1000n\)，只要 \(n\) 夠大，\(P_1>P_2\)。

    符號定義例子
    Big-O \(f(n)=O(g(n))\) iff 存在 \(c,n_0>0\) 使得對所有 \(n\ge n_0\)，\(f(n)\le c\,g(n)\) \(3n+2\le 4n\ (n\ge 2)\)；\(100n+6\le 101n\ (n\ge 6)\)；\(10n^2+4n+2\le 11n^2\ (n\ge 5)\)
    Omega \(f(n)=\Omega(g(n))\) iff 存在 \(c,n_0>0\) 使得對所有 \(n\ge n_0\)，\(f(n)\ge c\,g(n)\) \(3n+2\ge 3n\)；\(100n+6\ge 100n\)；\(10n^2+4n+2\ge n^2\)（皆 \(n\ge 1\)）
    Theta \(f(n)=\Theta(g(n))\) iff \(f(n)=O(g(n))\) 且 \(f(n)=\Omega(g(n))\) \(3n+2=\Theta(n)\)；\(100n+6=\Theta(n)\)；\(10n^2+4n+2=\Theta(n^2)\)
    💡
    Theorem 1.2 若 \(f(n)=a_mn^m+\cdots+a_1n+a_0\)，則 \(f(n)=O(n^m)\)。 \[f(n)\le |a_m|n^m+\cdots+|a_1|n+|a_0| \le n^m(|a_m|+\cdots+|a_1|+|a_0|)\le c\,n^m\quad(n\ge 1)\] → 最高次項的係數與低次項都不重要。
    📝
    練習（講義）
    • \(n^2-10n-6=O(n^2)\)、\(n+\log n=O(n)\)、\(n+n\log n=O(n\log n)\)、\(n^2+\log n=O(n^2)\)、\(2^n+n^{10000}=O(2^n)\)
    • \(n^4+1000n^3+n^2=O(n^4)\)？\(=O(n^5)\)？（講義留為是非題）

    常見的成長率

    複雜度名稱
    \(O(1)\)Constant time
    \(O(\log n)\)Logarithmic time
    \(O(n\log n)\)介於 \(O(\log n)\) 與 \(O(n^2)\) 之間
    \(O(n^2)\)Quadratic time
    \(O(n^3)\)Cubic time
    \(O(n^{100})\)Polynomial time
    \(O(2^n)\)Exponential time

    講義 p.49 的表格列出各成長率在不同 \(n\) 下的實際執行時間，例如 \(n=100\) 時 \(2^n\) 需要約 \(4\times10^{13}\) 年。

    Big-O 的性質

    • \(f(n)=O(g(n))\) 表示 \(g(n)\) 是 \(f(n)\) 的上界，例如 \(n=O(n)=O(n^{2.5})=O(n^3)\)，但我們希望 \(g(n)\) 越小越好。
    • Big-O 描述程式的 worst-case 執行時間。
    • 講義提問：\(f(n)=O(g(n))\) 是否能推得 \(g(n)=O(f(n))\)？（以問號圖示提問，未附答案）
    規則內容用途
    Rule of Sum\(f_1(n)+f_2(n)=O(\max(g_1(n),g_2(n)))\)依序執行的敘述
    Rule of Product\(f_1(n)\times f_2(n)=O(g_1(n)\times g_2(n))\)巢狀迴圈
     
    Rule of Product 範例for (i=0; i<n; i++) {        // O(n)
    for (j=0; j<n; j++)       // O(n)
        sum := sum + 1;        // O(1)
}                              // → O(n²)

    Binary Search 的複雜度

    第 1 次迭代搜尋 \(n\) 個值，第 2 次剩 \(n/2\)，第 3 次剩 \(n/4\)，…，第 \(k+1\) 次剩 \(n/2^k\)。當 \(n/2^k=1\) 時搜尋一定結束 → \(n=2^k\)，\(k=\log_2 n\) → worst case 為 \(O(\log_2 n)\)。

    Session1-Algorithms Handout.pdf p.43–55

    6. Performance Measurement

    • 實際執行程式，取得真正的空間與時間需求。
    • 程式中量測時間：方法 1 用 clock()（單位 clock ticks）；方法 2 用 time()（單位秒）。
    • 量測很短的程式時：重複執行很多次再取平均。

    自我測驗

    Q1. 演算法必須滿足哪五個條件？

    Input（零或多個輸入）、Output（至少一個輸出）、Definiteness（明確）、Finiteness（有限步結束）、Effectiveness（每個指令基本且容易計算）。

    Session1-Algorithms Handout.pdf p.4

    Q2. Space complexity \(S(P)=C+S_P(I)\) 中，\(C\) 與 \(S_P(I)\) 各包含什麼？

    \(C\) 是與輸入輸出無關的固定部分（指令空間、簡單變數、固定大小的結構變數、常數）；\(S_P(I)\) 是取決於問題實例的變動部分（被參照的變數、遞迴堆疊空間）。

    Session1-Algorithms Handout.pdf p.33

    Q3. \(T_{\text{Sum}}(n)=2n+3\)、\(T_{\text{Rsum}}(n)=2n+2\)，可以說 Rsum 比較快嗎？

    不行。每個 step 的執行時間不同；兩者成長率相同（都是 linear），時間複雜度相同。

    Session1-Algorithms Handout.pdf p.41–42

    Q4. 寫出 Big-O 的定義，並說明為什麼 \(10n^2+4n+2=O(n^2)\)。

    \(f(n)=O(g(n))\) iff 存在 \(c,n_0>0\)，使得對所有 \(n\ge n_0\) 都有 \(f(n)\le c\,g(n)\)。因為對所有 \(n\ge 5\)，\(10n^2+4n+2\le 11n^2\)。

    Session1-Algorithms Handout.pdf p.44

    Q5. 為什麼 Binary Search 的 worst case 是 \(O(\log_2 n)\)？

    每次迭代剩下的資料減半，第 \(k+1\) 次剩 \(n/2^k\)；當 \(n/2^k=1\) 時結束，得 \(k=\log_2 n\)。

    Session1-Algorithms Handout.pdf p.53
