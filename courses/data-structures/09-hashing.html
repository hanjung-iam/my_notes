    雜湊

    重點摘要

    • 平衡搜尋樹的 Get / Insert / Delete 為 \(O(\log n)\)；Hashing 可以做到 \(O(1)\)。
    • Hash table 有 \(b\) 個 bucket、每個 bucket \(s\) 個 slot；loading factor \(\alpha=n/(s\times b)\)。
    • Collision：key 對應到非空的 home bucket；Overflow：對應到已滿的 home bucket。好的 hash function 要容易計算、碰撞少。
    • 常見 hash function：Division、Mid-Square、Folding、Digit Analysis。
    • Dynamic (Extendable) Hashing 用 directory，只分裂溢位的 bucket；Linear Hashing 依線性順序輪流分裂 bucket。

    1. 為什麼需要 Hashing

    Indexing 方法Get / Insert / Delete
    Balanced (binary) search tree\(O(\log n)\)
    Hashing（static / dynamic）\(O(1)\)

    2. Static Hashing

    • 檔案區塊分成 \(M\) 個大小相同的 bucket；hash key 為 \(K\) 的記錄存在 bucket \(i=h(K)\)，\(h\) 為 hash function。
    • Hash table (ht)：存放 dictionary pairs 的容器，分成 \(b\) 個 bucket ht[0], …, ht[\(b-1\)]；每個 bucket 有 \(s\) 個 slot，通常 \(s=1\)。
    • Hash function \(h(k)\)：把 key 對應到 0 到 \(b-1\) 之間的整數（bucket）。
    名詞定義
    Key density\(n/T\)：\(n\) 為表中 pair 數，\(T\) 為所有可能 key 的總數
    Loading density / loading factor\(\alpha=n/(s\times b)\)
    Synonyms\(h(k_1)=h(k_2)\) 的兩個 key
    Collisionkey 被對應到非空的 home bucket
    Overflowkey 被對應到已滿的 home bucket
    💡
    重點
    • 每個 bucket 只有 1 個 slot 時，collision 與 overflow 會同時發生。
    • 新記錄對應到已滿的 bucket 時，存到 overflow file；同一 bucket 的 overflow 記錄可以串在一起（overflow pages）。
    • Slot 數少時，search、insert、delete 都可以在 \(O(1)\) 完成。
    ❗
    易錯：用開頭字母當 hash function 不好 key 可能偏向某些 bucket。好的 hash function 要容易計算、碰撞少。

    3. Hash Functions

    Uniform hash function：對隨機 key 不會偏向使用 hash table 的某部分；隨機選一個 key \(k\)，對所有 bucket \(i\)，\(P(h(k)=i)=1/b\)。

    Division\(h(k)=k\ \%\ D\)，key 為非負整數bucket 位址 0 到 \(D-1\)，所以至少要 \(b=D\) 個 bucket；\(D\) 用質數

    4. Dynamic Hashing（Extendable Hashing）

    處理 overflow 的方法：加 overflow pages、把 bucket 大小加倍、把 bucket 數加倍並重組…

    💡
    想法 bucket 滿了時，與其把整個檔案的 bucket 數加倍，不如使用一個指向 bucket 的 directory：把 directory 加倍（directory 比檔案小得多，加倍便宜），並只分裂溢位的那個 bucket，不需要 overflow page。
    • 用 hash 值 \(h(K)\) 的二進位表示來存取 directory。
    • Directory：大小為 \(2^d\) 的陣列，\(d\) 稱為 global depth；可以存在磁碟上，動態擴大或縮小；entry 指向存放記錄的磁碟 block。
    • 插入到已滿的 block 時，block 分裂成兩個，記錄重新分配到兩個 block，directory 也跟著更新。
    • Global depth = 所有 bucket 的 local depth 中的最大值，代表決定位址需要幾個 bits。
    📝
    例子（global depth = 2，看最後 2 bits）
    • Buckets：00 → {4, 12, 32, 16}、01 → {1, 5, 21}、10 → {10}、11 → {15, 7, 19}
    • 找 5（101）→ 最後兩位 01 → 第二個 bucket
    • Insert 13（1101）→ 01 bucket 還有空間，直接放入
    • Insert 20（10100）→ 00 bucket 已滿，需要分裂；改看最後 3 bits：000 → {32, 16}、100 → {4, 12, 20}，directory 加倍為 000–111，global depth 變成 3
    Local / Global depth 規則
    一開始所有 local depth 都等於 global depth（表示 bucket 總數所需的 bits 數）
    分裂時，若該 bucket 的 local depth = global depth，directory 必須加倍
    Directory 加倍時 global depth + 1；bucket 分裂時 local depth + 1

    Session9 - Hashing_240520_110816.pdf p.18–27

    5. Linear Hashing

    • 需要 overflow 區域；block 依線性順序分裂，以 round-robin 方式輪流，最終所有 bucket 都會被分裂。
    • 使用一族 hash functions \(h_0,h_1,h_2,\dots\)： \[h_i(\text{key})=h(\text{key})\bmod (2^iN),\quad N=\text{初始 bucket 數}\]
    • 若 \(N=2^{d_0}\)，則 \(h_i\) 看最後 \(d_i\) 個 bits，\(d_i=d_0+i\)；\(h_{i+1}\) 的範圍是 \(h_i\) 的兩倍。
    📝
    例子（Level 0，Next = 0）
    • Insert 43（101011）→ \(h_0\) 對應到 11 bucket，已滿 → 43 放進 overflow page，並分裂 Next 指向的 bucket（00）：用 \(h_1\) 看最後 3 bits，32（100000）留在 000，44（101100）、36（100100）移到新的 100 bucket；Next 變成 1。
    • Insert 29（11101）→ 對應的 bucket 溢位，放入 overflow page。
    💡
    與 Dynamic Hashing 的差別 Linear hashing 分裂的不一定是溢位的 bucket，而是 Next 指到的 bucket；溢位的記錄先放在 overflow page。

    Session9 - Hashing_240520_110816.pdf p.29–32

    自我測驗

    Q1. Collision 和 overflow 有什麼不同？什麼時候會同時發生？

    Collision 是 key 對應到非空的 home bucket；overflow 是對應到已滿的 home bucket。每個 bucket 只有 1 個 slot 時兩者同時發生。

    Session9 - Hashing_240520_110816.pdf p.9

    Q2. Loading factor 怎麼算？

    \(\alpha=n/(s\times b)\)，\(n\) 為 pair 數、\(s\) 為每個 bucket 的 slot 數、\(b\) 為 bucket 數。

    Session9 - Hashing_240520_110816.pdf p.8

    Q3. 使用 division hash function 時，\(D\) 要怎麼選？table 至少要多大？

    \(D\) 用質數；bucket 位址範圍是 0 到 \(D-1\)，所以 table 至少要有 \(b=D\) 個 bucket。

    Session9 - Hashing_240520_110816.pdf p.13

    Q4. Dynamic hashing 中，什麼時候 directory 要加倍？

    分裂 bucket 時，若該 bucket 的 local depth 等於 global depth，directory 必須加倍，global depth + 1。

    Session9 - Hashing_240520_110816.pdf p.27

    Q5. Linear hashing 的 \(h_i\) 怎麼定義？

    \(h_i(\text{key})=h(\text{key})\bmod(2^iN)\)，\(N\) 為初始 bucket 數；\(h_{i+1}\) 的範圍是 \(h_i\) 的兩倍。

    Session9 - Hashing_240520_110816.pdf p.29
